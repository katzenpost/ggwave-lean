# Test vectors

Everything here is output of C ggwave at commit
[`060aec7`](https://github.com/ggerganov/ggwave/tree/060aec73dd7123ccac200442f75bdc7369795ffe)
(MIT, Georgi Gerganov), regenerated by `tools/gen-vectors.sh` with the tools
`tools/build-c-ggwave.sh` builds. Nothing depends on Lean, so another port can
use the same files.

Conventions: hex strings are lowercase; samples are little-endian, `.i16` files
16-bit integers read as `x / 32768`. A test payload of `n` bytes with seed `s`
has byte `i` equal to `((i * 37 + s) & 255) ^ 0x5a`; most use `s = n`.

## waveforms/

Whole transmissions, C's `GGWAVE_SAMPLE_FORMAT_I16` output, from
`tools/ggwave-c.cpp`. `manifest.txt` lists each file's protocol id, fixed
length (0 for variable), output rate, volume, payload, operating rate and frame
size. The 24 at 48 kHz / 1024 are byte for byte the vectors of
[katzenpost/ggwave-rs](https://github.com/katzenpost/ggwave-rs) (commit
`b0435a8`); `p1-var-32-24000-512` is the voucher case at 24 kHz with 512-sample
frames. Audible and DT/MT waveforms are resampled to 16 kHz to keep them small.

## Components

From `tools/ggwave-vectors.cpp`, one JSON file per directory.

- `reed_solomon/reed_solomon.json`: the bundled `reed-solomon` code. `exp` (512
  bytes) and `log` (256 bytes) are the GF(2^8) tables; `mul`, `div`, `pow` are
  `[x, y, result]` and `inverse` is `[x, result]`. `encode` covers every code
  ggwave uses (the length header and payloads of 1 to 140 bytes): `msg_len`,
  `ecc_len`, `msg`, `block` (message then parity). `decode` corrupts `errors`
  bytes of a block at unknown positions, from none to past what the parity can
  correct; `decoded` is C's result, `null` when C rejects the block.
- `framing/framing.json`: each protocol, variable lengths 1, 5, 32, 140 and
  fixed lengths 1, 8, 32, 64. `coded` is the length header (variable mode),
  data and parity; `txs` lists, per Tx, C's tone indices from `txTones()`: tone
  `k` sounds data bit `k`, so `k / 16` is the tone group and `k % 16` the
  nibble sent in it.
- `encoder/encoder.json`: transmissions at their operating rate, with the
  FNV-1a 64 hash of each frame's float32 samples (`frames`) and of the whole
  waveform (`waveform`, `samples` long); the resampled case has no frames.
- `decoder/decoder.json` and its `.i16` inputs: the receiver fed one frame at a
  time, then `zero_frames_after` frames of silence. Each `trace` row is the
  state after that frame: `[frame, receiving, frames_to_record,
  frames_left_to_record, recv_duration_frames, payload or null]`. The cases are
  the 24 kHz voucher clean, noisy and cut off before its end marker, and a
  fixed-length message heard with every protocol enabled, where C reports a
  spurious payload before the real one.

There are no erasure vectors: ggwave never passes erasures to its Reed-Solomon
decoder, and that decoder's erasure path fails on erasures alone.
